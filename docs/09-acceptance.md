# 09 验收标准

## 1. 总体验收

| 维度 | 标准 |
|------|------|
| 功能 | M0–M5 全部出口达成；M6 至少 Ticket + Webhook |
| 多语言 | zh-CN / en-US 完整；切换即时；枚举/错误无漏翻 |

| 性能 | 列表 API P95 < 400ms（千级数据）；首屏 < 2s（内网） |

| 补遗 | 单号/幂等/安全/限流/导出符合 `13-spec-supplements.md` |
| 可维护 | 枚举/DTO 共享；文档与实现一致 |

## 2. 关键业务验收场景（BDD）

### AC-01 线索转化
```
Given 销售持有状态为 CULTIVATING 的线索 L
When 提交转化（新建客户+联系人+商机）
Then 客户/联系人/商机被创建且关联
And L.status = CONVERTED 且不可再编辑
And 任一实体详情可回溯线索来源
```

### AC-02 商机阶段与赢率
```
Given 商机 O 在 PROSPECTING（赢率 10）
When 拖到 NEGOTIATION（赢率 75）
Then 阶段历史记录 from/to 与操作者
And 看板卡片出现在新列
And 用非法阶段 id 更新 → 40900
```

### AC-03 折扣审批
```
Given 报价行折扣 30% 且阈值 20%
When 提交报价
Then 创建 ApprovalInstance(PENDING)
And 报价 status = SUBMITTED 不可 accept
When 审批通过
Then 报价 status = APPROVED
When 在 SUBMITTED 时调用 accept → 42200
```

### AC-04 合同回款核销
```
Given 生效合同总额 10 万，计划两期各 5 万
When 确认回款 3 万并核销到第一期
Then 合同 receivedAmount = 3 万
And 计划状态 PARTIAL
When 再回款 2 万核销同一期
Then 计划 PAID，receivedAmount = 5 万
And 回款累计 5 万
```

### AC-05 数据权限
```
Given 用户 A dataScope=SELF，用户 B 的客户
When A 查询客户列表
Then 看不到 B 的客户
When A GET B 客户 id
Then 40301
When 同时 B share 给 A
Then A 可读
```

### AC-06 多租户
```
Given 租户 T1/T2
When T1 用户访问 T2 数据 id
Then 40400（禁止枚举存在性）
```

### AC-07 公开表单获客
```
When 匿名提交表单
Then 创建 Lead source=WEB_FORM，status=NEW
And 60s 内同 IP 超 5 次 → 42900
```

### AC-08 多语言
```
Given 用户界面语言为 en-US
When 打开商机列表并查看状态 Tag / 按钮
Then 文案来自 en-US 词典，无中文硬编码残留
And 日期、金额按 en-US + 用户时区格式化
When 切换回 zh-CN
Then 界面立即切换且刷新后保持
```

### AC-09 手机端核心路径
```
Given 视口宽度 390
When 使用底部 Tab 完成：登录 → 今日待办 → 新建跟进 NOTE → 客户详情
Then 主路径无水平错乱，触控目标 ≥44px
And 无定位权限时打卡可改手工地址
```

### AC-10 三端冒烟（iOS / Android / 鸿蒙）
```
Given 分别在 iOS、Android、HarmonyOS 安装包启动 App
When 完成登录 → 待办 → 跟进 →（定位允许则）打卡
Then 主链路可用，Bridge 不抛未捕获错误
And 拒绝定位时可手工地址保存跟进
```

### AC-11 冻结门禁
```
Given 实现完成
Then 业务代码仅为 TypeScript
And 主存储仅为 PostgreSQL（+Redis 缓存/队列）
And P0 功能 F01–F14 可演示
```

### AC-12 幂等与单号
```
When 用同一 Idempotency-Key 重复确认回款
Then 不双记金额
And 同日新建报价/合同单号不重复
```
